HTTP DELETE Method Documentation

Purpose

The DELETE method requests that the origin server delete the resource identified by the Request-URI.

Usage

The client sends a DELETE request to the server, specifying the target resource's URL.

DELETE /path/to/resource.txt HTTP/1.1
Host: example.com
User-Agent: curl/7.64.1
Accept: */*

Request Headers

Common request headers for a DELETE request include:

  • Host: The domain name of the server (required).
  • Authorization: (Optional) Credentials for authenticating the client to the server.

A DELETE request typically does not have a request body, although it is not forbidden by the HTTP specification. Servers usually ignore any request body sent with a DELETE request.

Response Status Codes

Status Code Description
200 OK The request has succeeded. The response body might include a representation of the status. (Less common for DELETE than 204)
202 Accepted The request has been accepted for processing, but the processing has not been completed.
204 No Content The request has succeeded and there is no additional content to send in the response payload body. This is a common successful response for DELETE.
403 Forbidden The client does not have access rights to the content, or the server refuses to delete a directory.
404 Not Found The server can not find the requested resource.
405 Method Not Allowed The method is not allowed for the requested resource. This can happen if the server configuration disallows DELETE for the path.
500 Internal Server Error The server encountered an unexpected condition that prevented it from fulfilling the request. This might occur due to file system errors during deletion.

Example (using curl)

Assuming a web server running on localhost:8080 and a file named example.txt in its root directory:

# To delete 'example.txt'
curl -v -X DELETE http://localhost:8080/example.txt

Expected successful response (Status 204 No Content):

< HTTP/1.1 204 No Content
< Date: [Current Date and Time]
< Server: [Your Webserver Name]
< Connection: close
<

DELETE method tutorial

This repo already parses DELETE in src/http/HTTPRequest.cpp, but for it to work end-to-end you must:

  • Dispatch the method from RequestHandler
  • Enforce allow_methods for the matched LocationBlock
  • Call the actual deleter (src/http/Methods/Delete.cpp)

Where to call DELETE

The correct insertion point is the HTTP method dispatcher:

  • src/http/RequestHandler.cpp → RequestHandler::handleDELETE(...)

That function should:

  1. matchLocation(request.getTarget())
  2. Verify allow_methods includes DELETE
  3. Call Delete::handle(request, response, location)

Also, because Client stores a reusable HttpResponse, you should reset response at the start of:

  • src/http/RequestHandler.cpp → RequestHandler::process(...)

This prevents previous requests’ headers/bodies from leaking into the current response (important for 204 No Content).

What Delete::handle is expected to do

src/http/Methods/Delete.cpp should:

  • Map the request target to a filesystem path under the location/server root
  • Refuse traversal outside root (return 403)
  • Refuse deleting directories (return 403)
  • Return:
    • 204 No Content on success (with empty body)
    • 404 Not Found if the target does not exist
    • 403 Forbidden on permission errors
    • 500 Internal Server Error on unexpected failures

Minimal config to test DELETE

Add a location that allows DELETE (example for port 8080):

location /delete {
    root ./www;
    allow_methods DELETE;
}

Manual test cases

Build + run:

make
./webserv config/example.conf

Create a file and delete it (expect 204):

mkdir -p www/delete
echo hi > www/delete/a.txt
curl -i -X DELETE http://127.0.0.1:8080/delete/a.txt

Verify it is removed:

ls -l www/delete/a.txt

Not found (expect 404):

curl -i -X DELETE http://127.0.0.1:8080/delete/missing.txt

Directory delete blocked (expect 403):

mkdir -p www/delete/dir
curl -i -X DELETE http://127.0.0.1:8080/delete/dir

Traversal blocked (expect 403):

curl -i -X DELETE 'http://127.0.0.1:8080/delete/../config/example.conf'

Raw HTTP (no curl), to validate parsing/response formatting:

printf 'DELETE /delete/a.txt HTTP/1.1\r\nHost: localhost\r\n\r\n' | nc 127.0.0.1 8080

Troubleshooting

  • Getting 405 Method Not Allowed: your matched location does not include DELETE in allow_methods.
  • Getting 403 Forbidden: you’re deleting a directory, leaving the configured root, or the process lacks permissions on the parent directory.
