Mental Model

From config file to epoll-able sockets

Configuration parsing runs once at boot. It reads a .conf, shouts if a path is wrong, and hands you ready-to-bind server descriptions. After that, the IO loop only touches C++ objects, never raw text.

Keep it simple: parse → build sockets → hand FDs to epoll/kqueue. No magical background work, so you can trust what each getter returns.

How to use it

Step-by-step workflow

Do this once during startup. The goal: end up with non-blocking listening sockets plus route data that your HTTP worker can consult per request.

  1. Parse once and keep the vector. Instantiate ServerConfigParser, call createCluster(path), then store the returned std::vector<WebserverConfig> for the entire runtime.
  2. Build sockets. For every WebserverConfig, call setupWebserver(). It handles socket(), SO_REUSEADDR, fills sockaddr_in, and binds using getHost() + getPort().
  3. Let the caller own listen + blocking flags. Call listen(server.getFdX(), backlog), set O_NONBLOCK if needed, and plug the descriptor into your multiplexer (epoll/kqueue/select/poll).
  4. Answer requests with the stored data. When a connection arrives, pick the matching WebserverConfig (host + port) and use getLocationBlockByName(), getIndex(), getMaxBodySize(), etc., to know which file to open or which CGI binary to launch. 
// Parse the configuration file
ServerConfigParser parser;
parser.createCluster("config/default.conf");
std::vector<WebserverConfig> servers = parser.getServers();

// Prepare each listening socket for multiplexing
for (WebserverConfig &server : servers) {
  server.setupWebserver();                  // socket + bind using getHost()/getPort()
  listen(server.getFdX(), 128);             // backlog is your call
  fcntl(server.getFdX(), F_SETFL, O_NONBLOCK);
  epoll.add(server.getFdX(), EPOLLIN);      // or kqueue/select wrapper
}

ConfigurationFile

Tiny helper for file metadata and content.

  • getFilename() std::string

    Purpose: Returns the full path of the file currently being parsed. Use it: whenever you log parser errors or show which config produced a faulty socket. Helpful when teammates juggle different conf files.

  • getSize() size_t

    Purpose: Provides the file size in bytes. Use it: to guard against empty configs or to pre-allocate buffers before reading.

  • getTypePath(path) int

    Purpose: Tells you if path is a file (1), directory (2), or invalid (-1). Use it: while validating root, alias, and CGI paths before the server boots.

  • checkFile(path, mode) int

    Purpose: Wrapper around access() to verify read/write/execute permissions. Use it: to fail fast if an error page or CGI script is unreadable.

  • doesFileExist(root, name) int

    Purpose: Checks whether root + name resolves to a valid entry. Use it: when toggling through fallback indexes during validation.

  • getFileContent(path) std::string

    Purpose: Reads the file and returns it as a plain string. Use it: to feed the parser or to dump configs in integration tests.

ServerConfigParser

Consumes the raw file and builds server objects.

  • getServers() vector<WebserverConfig>

    Purpose: Main payload: returns every parsed virtual server. Use it: once, store the vector, and iterate to set up listeners and expose routing data to the HTTP workers.

  • print(std::ostream&) int

    Purpose: Dumps the full configuration tree to an output stream. Use it: when diffing behaviors or verifying that directives were parsed as expected.

WebserverConfig

One virtual host: holds socket details and locations.

  • getServerName() const std::string&

    Purpose: Returns the configured server_name. Use it: to match HTTP Host headers when many names share the same IP:port pair.

  • getPort() const uint16_t&

    Purpose: Provides the listening port. Use it: to fill sockaddr_in.sin_port before bind/listen so your socket ends up on the right TCP port.

  • getHost() const in_addr_t&

    Purpose: Stores the host IP (already in network-byte-order). Use it: while building sockaddr_in to listen on 0.0.0.0, 127.0.0.1, etc.

  • getMaxBodySize() const size_t&

    Purpose: Global request-body limit for this server. Use it: as the default cap when HTTP workers read POST/PUT payloads.

  • getLocationBlocks() const vector<LB>&

    Purpose: Gives direct access to every raw location block. Use it: for bulk inspection or tooling; most runtime lookups should go through getLocationBlockByName().

  • getRoot() const std::string&

    Purpose: The default document root. Use it: whenever no location block overrides the filesystem path.

  • getErrorPages() const map<short, string>&

    Purpose: Maps HTTP status codes to static files. Use it: when building error responses; fall back to a generic template if the map has no entry.

  • getIndex() const std::string&

    Purpose: Default file name when a directory is requested (usually index.html). Use it: after resolving the root path; append this name before touching the filesystem so directories return a file instead of 403.

  • getAutoindex() const bool&

    Purpose: Indicates whether to generate directory listings automatically. Use it: when getIndex() fails—if true, emit a listing; otherwise respond with 403.

  • getPathErrorPage(code) std::string

    Purpose: Shortcut to grab the error page path for a specific status. Use it: inside your response builder to avoid manually touching the map.

  • getLocationBlockByName(uri) iterator

    Purpose: Finds the best matching LocationBlock for a URI. Use it: right after parsing the HTTP request to know which limits, CGI map, or alias apply.

  • getFdX() int

    Purpose: Returns the bound socket file descriptor. Use it: to register listeners in epoll/kqueue/select and when you call accept().

LocationBlock

Routing leaf: methods, CGI mapping, limits.

  • getRoot() const std::string&

    Purpose: Path override for this location. Use it: when serving files so URLs like /images can map to /mnt/data/pics.

  • getPath() const std::string&

    Purpose: The URI prefix this block matches. Use it: to debug why a request hit a specific block.

  • getIndex() const std::string&

    Purpose: Per-location default file. Use it: before directory listings—this overrides the server-level index when the URI lives inside the location.

  • getAutoindex() const bool&

    Purpose: Location-specific directory listing flag. Use it: to decide if you may generate HTML listings for this path.

  • getReturn() const std::string&

    Purpose: Stores a redirection target. Use it: if present, respond with a 3xx status pointing at this string instead of serving a file.

  • getAlias() const std::string&

    Purpose: Remaps the matching URI to another filesystem path. Use it: before building the final file path, replacing the leading URI portion.

  • getMethods() const vector<short>&

    Purpose: Lists allowed HTTP methods (stored as enums). Use it: to reject unsupported verbs with 405.

  • getCgiExtensions() const vector<string>&

    Purpose: File extensions that should trigger CGI execution. Use it: when routing .php, .py, etc., to the CGI runner.

  • getCgiPaths() const vector<string>&

    Purpose: Holds the interpreter paths (one per extension). Use it: together with getCgiExtensions() when launching CGI scripts.

  • getExtensionToCgiMap() const map<string, string>&

    Purpose: Direct lookup table for extension → interpreter. Use it: at runtime to skip manual matching.

  • getMaxBodySize() const u_long&

    Purpose: Per-location upload limit. Use it: to enforce tighter quotas on sensitive endpoints such as /upload.

In practice

Operational cues

Defaults & Guards

Missing directives fall back to sane defaults: host → 127.0.0.1, index → index.html, and client_max_body_size → kDefaultMaxBodySize. Validation ensures roots, aliases, error pages, and CGI scripts point to readable paths before the event loop ever starts.

Routing Usage

Pick the matching WebserverConfig by host + port, then call getLocationBlockByName(). From there you can read getRoot(), getAlias(), getIndex(), and method lists to decide how to respond.

Multiplexed Startup

The only contract the event layer needs is a bound listening fd. setupWebserver() builds and binds it for you; grab it with getFdX(). You keep control over backlog, non-blocking flags, and which readiness bits to monitor.

Next Step

Hand the parsed config to the multiplexed loop

Below is a tiny reference snippet that shows how the parsing results travel into a homemade epoll wrapper and how HTTP routing later reuses the stored WebserverConfig and LocationBlock objects.

// 1. Parse configuration
ServerConfigParser parser;
parser.createCluster("config/default.conf");
std::vector<WebserverConfig> servers = parser.getServers();

struct ListenerSlot {
  int fd;
  uint16_t port;
  in_addr_t host;
  const WebserverConfig* config;
};

std::vector<ListenerSlot> listeners;

for (WebserverConfig &server : servers) {
  server.setupWebserver();
  listen(server.getFdX(), 64);
  fcntl(server.getFdX(), F_SETFL, O_NONBLOCK);

  listeners.push_back(ListenerSlot{
    server.getFdX(),
    server.getPort(),
    server.getHost(),
    &server
  });

  loop.add(server.getFdX(), EPOLLIN, &server); // loop = epoll/kqueue wrapper
}

// 2. Later, inside the event loop
void onReadable(int listenerFd) {
  const WebserverConfig &cfg = *loop.findPayload(listenerFd);
  const LocationBlock &loc = *cfg.getLocationBlockByName(request.path);

  std::string root = loc.getRoot().empty() ? cfg.getRoot() : loc.getRoot();
  std::string file = root + request.path;
  if (isDirectory(file)) {
    const std::string &index = loc.getIndex().empty() ? cfg.getIndex() : loc.getIndex();
    file += index;
  }

  enforceBodyLimit(request, loc.getMaxBodySize(), cfg.getMaxBodySize());
  sendFile(clientFd, file);
}

Swap loop.add, loop.findPayload, and sendFile with your actual abstractions—the core idea is to keep a pointer to the original config object so multiplexing and HTTP logic stay synchronized.
