CGI

Scripts executed safely and asynchronously.

CGI support is implemented in src/cgi/CgiHandler.cpp and coordinated by Server. Scripts are launched only when a location defines cgi_ext and cgi_path.

Routing to CGI

RequestHandler::handleCGI checks the request target against the extension map built in LocationBlock. The script path is resolved using the location root.

Environment variables

The handler sets a compact CGI environment:

  • GATEWAY_INTERFACE, SERVER_PROTOCOL
  • SERVER_SOFTWARE
  • REQUEST_METHOD, REQUEST_URI
  • SCRIPT_FILENAME, SCRIPT_NAME
  • QUERY_STRING
  • CONTENT_LENGTH, CONTENT_TYPE
  • HTTP_COOKIE, HTTP_USER_AGENT
  • HTTP_ACCEPT, HTTP_HOST

Process model

CgiHandler::spawn forks, connects stdin/stdout to pipes, and execs the interpreter (from config or by extension). The parent uses non-blocking pipes and epoll readiness for I/O.

Default interpreters are mapped by extension (py, pl, php, rb, sh) when no explicit cgi_path is provided.

Timeout and output limits

  • Timeout: 5 seconds.
  • Max output buffer: 16 MB.
  • On overflow or failure: 502 Bad Gateway.
  • On timeout: 504 Gateway Timeout.

Output parsing

CGI output headers are parsed if present. A Status header sets the response status. If Location is present and no status is set, the response defaults to 302.

CGI execution is coordinated inside Server::handleCgiEvent.
