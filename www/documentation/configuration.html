Configuration

NGINX inspired, strictly validated.

Configuration files are parsed by ServerConfigParser. The parser enforces trailing semicolons, validates paths, and prevents duplicated directives.

Server block directives

Directive Meaning
listen TCP port to bind.
host IPv4 address. localhost maps to 0.0.0.0.
server_name Optional name (stored, not used for routing).
root Document root. Must resolve to a directory.
index Default file for directory requests.
client_max_body_size Max request body size. Supports M or G suffix.
autoindex Enable directory listing when no index file exists.
error_page Custom error page path for a status code.

Location directives

  • allow_methods (also methods and allowed_methods)
  • root, index, autoindex
  • return (simple redirect)
  • alias (path remapping)
  • client_max_body_size
  • cgi_ext and cgi_path
The /cgi-bin location is treated specially. It must declare cgi_ext, cgi_path, and index, and it forbids autoindex, alias, and return.

Validation rules

  • Every directive must end with a semicolon.
  • Duplicate directives in the same block are rejected.
  • Server blocks cannot share the same host and port.
  • Location paths must begin with /.
  • CGI extensions and paths must be paired 1:1.

Example snippet

server {
  listen 8085;
  host 127.0.0.1;
  root ./www;
  index index.html;
  autoindex on;

  location /upload {
    allow_methods POST GET DELETE;
    client_max_body_size 2G;
  }

  location /cgi-bin {
    root ./www;
    cgi_ext .py .sh .pl .rb .php;
    cgi_path /usr/bin/python3 /bin/bash /usr/bin/perl /usr/bin/ruby /usr/bin/php;
    index handler.py;
  }
}
Configuration parsing lives in src/config and is intentionally strict to catch mistakes early.
