Event Loop

Single epoll loop, many responsibilities.

The server uses a single epoll instance to track listening sockets, client sockets, CGI pipes, and signal notifications.

Epoll manager

EpollManager is a small singleton that wraps epoll_ctl and epoll_wait, with verbose logging when debug mode is enabled.

Accept loop

Server::acceptClient accepts all available connections, marks client sockets non-blocking, and registers them with epoll for EPOLLIN and EPOLLRDHUP.

Dispatch by file descriptor

Helpers::findServerByFd determines whether an fd is a listening socket, a client socket, or a CGI pipe. The main loop dispatches accordingly.

Signals in epoll

SignalHandling installs a self-pipe to translate SIGINT, SIGTERM, and SIGQUIT into epoll events. This keeps signal handling non-blocking and predictable.

Graceful shutdown closes all clients and listening sockets before destroying the epoll instance.
The loop logic lives in src/main.cpp and src/server/server.cpp.
