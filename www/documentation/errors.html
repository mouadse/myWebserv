Errors

Clear status codes, simple HTML fallbacks.

Errors are generated in multiple layers: request parsing, method handlers, file system checks, and CGI execution.

Parsing errors

HTTPRequest reports validation errors which RequestHandler maps to status codes such as 400, 405, 411, 413, 414, 431, and 505. The response body is a simple HTML message.

Method restrictions

When a location forbids a method, Webserv returns 405 and includes an Allow header listing permitted methods.

File system errors

  • 404 for missing files.
  • 403 for permission issues or forbidden listings.
  • 500 for unexpected file read failures.
  • 416 for invalid range requests.

CGI failures

  • 502 for invalid output or non-zero exit status.
  • 504 when the CGI timeout is exceeded.
  • 502 if output exceeds the 16 MB buffer cap.

Custom error pages

error_page directives are parsed and validated in WebserverConfig. The current request handlers still generate built-in HTML bodies, so custom error pages are not yet wired into response generation.

Error handling code lives mostly in RequestHandler and the per-method handlers.
