Methods

Practical implementations, no surprises.

Method handlers live under src/http/Methods. They enforce per-location method restrictions and shape the final response.

GET

  • Resolves the path using root or alias.
  • Serves index for directories when present.
  • Autoindex generates a simple directory listing.
  • Supports byte ranges with Accept-Ranges.
  • Streams large files and caches smaller ones (1 MB max).
MIME types are mapped by file extension in Get::getMimeType.

POST

The POST handler supports two paths:

  • Raw body uploads: writes the body to the target path or, if the target is a directory, generates a timestamped filename based on Content-Type.
  • multipart/form-data: extracts one file using the boundary and writes it after filename sanitization.

Successful uploads return 201 Created and include a Location header.

DELETE

  • Refuses to delete the server root.
  • Uses realpath to avoid path traversal.
  • Prevents deletion of directories.
  • Returns 204 No Content on success.

Method authorization

Each location defines allowed methods. If a method is not allowed, Webserv responds with 405 and an Allow header built from the location rules.

The request parser currently only accepts GET, POST, and DELETE. HEAD support exists in the handler but is rejected earlier.
The method implementations are in src/http/Methods and called by RequestHandler.
