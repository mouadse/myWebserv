Architecture

Small modules, clean flow.

Webserv is structured around a single event loop, with a clean separation between configuration parsing, request processing, and response streaming. The goal is steady, non-blocking work across all connections.

Startup and configuration

Entry point src/main.cpp parses the configuration file via ServerConfigParser. Each WebserverConfig becomes a Server instance, bound to its host and port. 

main
  -> ServerConfigParser::createCluster
  -> vector<WebserverConfig>
  -> vector<Server>

Event loop

A singleton EpollManager owns the epoll file descriptor. The loop waits on listening sockets, client sockets, CGI pipes, and the signal pipe. 

epoll_wait
  -> acceptClient
  -> readClient / writeClient
  -> handleCgiEvent

Request flow

  1. Socket data is fed into HTTPRequest.
  2. When complete, RequestHandler builds a response.
  3. File responses are streamed; small files may be cached.
  4. Buffers are sent through Server::writeClient.

CGI flow

If a request targets a configured CGI path, the handler prepares a CgiTask. The server spawns the script, connects pipes, and resumes the epoll loop while the CGI executes.

CGI timeouts are enforced at 5 seconds, with a 16 MB output cap.
Modules are designed to be independent: config, HTTP, CGI, and loop logic can evolve without cross-cutting changes.
